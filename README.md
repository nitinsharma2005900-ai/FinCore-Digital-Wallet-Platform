# FinCore

Educational digital wallet. **Simulation Only – No Real Money.**

Work in progress. See `ASSESSMENT_MATRIX.md` for evidence-based status. Do not treat this repository as production-ready or as a completed assessment submission.

The intended stack is Next.js/React/TypeScript, Express, PostgreSQL/Prisma, Redis/BullMQ, and a separate Python FastAPI service. PostgreSQL 17 portable binaries, Redis and Mailpit are installed in the ignored `.tools` directory for Windows development without administrator privileges.

## Local setup

From PowerShell in this directory:

```powershell
.\scripts\Setup.ps1
.\scripts\Start.ps1
```

Setup generates strong local secrets in ignored `.env`. Never commit that file. Synthetic account credentials are generated by the seed script into `.runtime/demo-credentials.json`. Demo emails: `customer@fincore.test`, `recipient@fincore.test`, `support@fincore.test`, `operations@fincore.test`, `finance@fincore.test`, `admin@fincore.test`.

Frontend: http://127.0.0.1:3000 · API health: http://127.0.0.1:4000/health · analytics docs: http://127.0.0.1:8000/docs · Mailpit: http://127.0.0.1:8025. Use explicit IPv4: another process occupies IPv6 port 4000. Availability must be checked after startup; the launcher itself does not prove readiness.

```powershell
npm.cmd run typecheck
npm.cmd run lint
.venv/Scripts/python.exe -m pytest services/financial-analytics
npm.cmd test
npm.cmd run build
.\scripts\Stop.ps1
```

Prepare financial integration tests with `node scripts/prepare-tests.mjs`, then `npm.cmd test`. These tests require the dedicated `fincore_test` PostgreSQL database and must never be pointed at the demo database.

## Financial semantics

Wallets represent customer liabilities. CREDIT increases the displayed wallet balance; DEBIT decreases it. Treasury is a synthetic clearing account permitted to have a negative journal balance. Customer wallets cannot have negative available balances. Available = posted credits − posted debits − active holds. Amounts are exact PostgreSQL NUMERIC(20,2); JavaScript domain calculations use Decimal.js and Python uses Decimal with ROUND_HALF_EVEN. Chart rendering and currency presentation convert strings to numbers only for display.

Every posted transaction has exactly two equal entries. Deferred database triggers reject incomplete or unbalanced posting. Historical entries and posted headers are immutable. Compensations create new entries; they do not rewrite history. The runtime role does not own tables. Transfers use READ COMMITTED transactions, sorted wallet row locks, scoped advisory locks and durable payload-bound idempotency records.

## Provider limitations

Local payment simulation is implemented separately from Stripe. Stripe test intent creation and signed webhook handling are written but unverified with external credentials. Stripe refund orchestration is explicitly rejected before any money movement. Email/SMS delivery and the worker are not implemented yet. Simulated MFA codes are displayed only outside production; production MFA activation is blocked pending secure delivery.

Docker is absent on this machine. No cloud deployment or GitHub publication has occurred. The authenticated GitHub account is not a designated submission repository. Select a repository before publishing.
